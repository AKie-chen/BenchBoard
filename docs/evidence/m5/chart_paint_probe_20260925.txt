问题（用户报告）
------------------------------------------------------------------------------
M5 重构出 ChartContext + 三图之后：可以编译、可以运行、界面正常，
但【三条曲线一条都画不出来】。零编译警告、零运行报错。

------------------------------------------------------------------------------
tools/probes/m5_chart_paint_probe.cpp
  Part A  裸 QChart 的 attachAxis / addSeries 顺序 A/B 对照
  Part B  真实 src/RealtimeChartView.cpp，喂 10 个样本，逐张图报数
  Part C  按 Qt 要求的顺序重建三图（= 修复后的可执行规格）
判据：渲染成 QImage 后统计【彩色像素】（|max(R,G,B) - min(R,G,B)| > 30）。
      轴 / 刻度 / 标题文字都是灰阶 → 不计入；QLineSeries 是蓝色 → 计入。
      > 200 才算"真的画出了曲线"。
构建：Release / Qt 6.10.2 / QT_QPA_PLATFORM=offscreen

★ 第二类成因（Part C 第一版撞出来的，已记录）：
  第一版 Part C 忘了给 RPS 做 Y 轴自适应，Y 轴还是初值 0~100，

  彩色像素同样是 0，表现和"没绑轴"一模一样。
  → 诊断"有图无线"时必须【先看 attachedAxes，再看 Y 轴范围】，
    只看"有没有像素"会把两个成因混成一个。

结论
------------------------------------------------------------------------------
成因①（致命，三图全中）：attachAxis() 必须在 chart->addSeries() 【之后】调用。
      先 attachAxis 时 Qt 直接拒绝并返回 false；返回值被丢弃，
      唯一的提示是一条 qWarning。改动量：把 6 处 addSeries 提到 attachAxis 之前。

成因②（致命，同族）：m_p95Series 少了 chart->addSeries()。

为什么"零报错"：Qt 的 qWarning 在 Windows 上走 OutputDebugString，
  只有挂着调试器（VS / VS Code 的 Debug Console）才看得见。
  直接跑 exe 或在普通终端跑 —— 一个字符都不会显示。

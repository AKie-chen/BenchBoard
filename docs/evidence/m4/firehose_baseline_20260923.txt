[4] 复现用户那次的推算
----------------------------------------------------------------------------
99,710 请求 × 14.0 行/请求            = 1,396,000 行  （约 350 MB）
app 的消费能力（Debug）= 14,800 ~ 21,300 行/s（取区间两端各算一次）
  10 s 内吃掉                          ≈ 148,000 ~ 213,000 行
  积压                                 ≈ 1,183,000 ~ 1,248,000 行
  排空积压需要                         ≈ 56 s ~ 84 s

  预测「点开始 → 界面宣布结束」总时长   ≈ 66 s ~ 94 s
  用户实测                             ≈ 60 s（"快一分钟"）—— 落在预测区间内

积压内存：QProcess 在 Windows 上用重叠 IO 把管道往自己的内部缓冲里抽干，
不关心消费方进度，所以这 ≤ 350 MB 会实实在在地落在进程内存里。


[5] 附带实测：QProcess 启动失败在界面上是完全静默的
----------------------------------------------------------------------------
探针：tools/probes/qprocess_start_check.cpp（本机当前环境下 QProcess 一律启动失败，
      与本项目无关，仅用于取证错误路径）

t=    0ms  [stateChanged]   Starting
t=   10ms  [errorOccurred]  FailedToStart  (pipe: 系统找不到指定的文件。)
t=   10ms  [stateChanged]   NotRunning

同一现象在真实 MainWindow 上的表现（tools/probes/firehose_ui_probe.cpp 抓的截图）：
  日志区  : 只有一行「引擎已启动：」（6 个字符）
  状态栏左: 已采集 0 点 | 请求 0 次 | 失败 0 | 已跑 219.1s
  状态栏右: 引擎：运行中
  按钮    : 「开始压测」灰、「停止」可点
             —— 与「k6 正在跑但还没输出」肉眼完全无法区分，
                而且永远停在「运行中」（finished 永远不会来）。

原因：MainWindow.cpp 只 connect 了
        readyReadStandardOutput / readyReadStandardError / finished，
      没有 connect QProcess::errorOccurred。
      onEngineFinished 里对错过的错误路径没有兜底。
